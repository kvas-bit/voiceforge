# VoiceForge — Functionality Audit (2026-05-10)

## TL;DR

- **It is a real, native SwiftUI macOS app.** No WKWebView, no Electron, no JavaScript runtime. The "bar at the top" the user noticed is the *default* macOS `NSWindow` titlebar — the `WindowGroup` never opts into `.windowStyle(.hiddenTitleBar)` and there is no `.toolbar`, so AppKit gives it the standard grey titlebar with "Generation + History" written in it. That bar collides visually with the app's in-canvas branding header in the sidebar (which renders a *second* "VoiceForge" wordmark just below it), which is what makes the whole window feel non‑native and "Electron‑ish".
- **It builds.** `swift build` is clean (no warnings, no errors).
- **Tests pass.** `swift test` → 7 / 7 across 4 suites (`PromptFormatterTests`, `SpeechGenerationServiceTests`, `StoreTests`, `AppViewModelTests`).
- **It can actually produce audio,** provided `mlx-speech` is installed in the user's shell `PATH`. The TTS backend is **not** ElevenLabs — it is the local [`mlx-speech`](https://github.com/Blaizzy/mlx-audio) CLI running Fish Audio S2 Pro on Apple Silicon. The app shells out via `/bin/zsh -lc "mlx-speech tts --model fish-s2-pro --text … --reference-audio … --reference-text … -o ~/voiceforge/voiceforge_output.wav"`. `mlx-speech` is installed at `/Users/kaviantoniovasudeo/.local/bin/mlx-speech`, confirmed via `mlx-speech tts --help`.
- **Audio‑tag plumbing works** for the local backend's grammar: `PromptFormatter` accepts `*excited*` and `[whisper]` syntax, canonicalises tags via an alias map (`whisper` → `whispering softly and quietly`, `laugh` → `laughing lightly`, etc.), dedupes them, prepends a global tone, then injects them inline into the `--text` argument that Fish S2 Pro consumes. It is **not** the ElevenLabs `[whispers]` / `[laughs]` / `[sighs]` schema — it is a descriptive‑prose schema, which is what Fish S2 Pro expects.
- **Playback works.** `AudioPlayerController` wraps `AVAudioPlayer`, loads the output WAV after each render, exposes play/pause/stop, and broadcasts `isPlaying` via `@Published`.
- **Persistence works.** `UserDefaults` for reference path/transcript/emotion + voice presets; JSON file at `~/Library/Application Support/VoiceForge/history.json` for render history.

## What actually works

- ✅ Prompt formatting with `*tag*` and `[tag]` syntax, alias expansion, deduplication.
- ✅ Generation via real `mlx-speech` shell-out, with fully captured stdout + stderr surfaced in a status panel.
- ✅ WAV playback via `AVAudioPlayer`.
- ✅ Reference audio file picker (`NSOpenPanel` with `.audio` UTType).
- ✅ Saving output to a user-chosen path (`NSSavePanel`), and "Reveal in Finder" (`NSWorkspace.activateFileViewerSelecting`).
- ✅ Voice presets (name + reference audio path + reference transcript), persisted to `UserDefaults`.
- ✅ History panel (timestamped entries, click to reuse, persists to JSON).
- ✅ Persistence of the reference fields across launches.
- ✅ Quick-tag chips that splice a `[tag]` into the script editor at the caret via an `insertTrigger` counter pattern.
- ✅ UI-test harness (`--uitest-reset-state`, `--uitest-mock-generation`, env-var seeding for reference paths and source text) with a deterministic WAV synthesiser so UI tests don't need a real model.

## What is broken, stubbed, or off-brief

The brief is "ElevenLabs clone". The current build is closer to "lightweight wrapper around a local Fish S2 Pro CLI" — functional, but conceptually narrow. The following are gaps relative to the brief, in priority order:

1. **Window chrome / "the bar at the top".** `VoiceForgeApp` declares a plain `WindowGroup`, which produces a standard `NSWindow` with the default titlebar. The titlebar is fine in isolation but feels redundant because the in-app sidebar header re-renders a "VoiceForge" wordmark right beneath it. There is **no** `.windowStyle(.hiddenTitleBar)`, **no** `.toolbar`, **no** `.containerBackground`, and **no** unified titlebar. Result: a non-native vibe even though the underlying view tree is 100 % SwiftUI.
2. **No `NavigationSplitView`.** Navigation is a hand-rolled HStack with three fixed-width panels. There is no real "sidebar destinations" model — "Voice library" and "Workspace settings" sidebar rows are decorative (they don't change anything when tapped); the actual surfaces are sheets behind two square buttons.
3. **No `Inspector`.** What ElevenLabs puts in a right inspector (voice, model, sliders, character counter) is currently a vertical stack of decorative panels that don't reflect any tunable parameters. The CLI does take `--max-new-tokens` and `--model`; neither is exposed.
4. **No real voice library.** The "Voices" surface only stores name + reference clip + transcript triples. No filters, no preview-on-hover, no metadata (gender / accent / age / use case), no community voices.
5. **No model picker.** `mlx-speech` supports any of its bundled aliases (Fish S2 Pro, Step Audio, MOSS, etc.). The Swift code hard-codes `fish-s2-pro`.
6. **No "ElevenLabs‑style" tag schema.** Tags like `[whispers]`, `[laughs]`, `[sighs]`, `[sarcastic]` get rewritten to descriptive prose by `PromptFormatter`, which is correct for Fish S2 Pro but means the redesign needs to teach users that the chips correspond to the *current backend*'s grammar, not literal ElevenLabs strings.
7. **No autocomplete on `[`.** Tag insertion is via a separate row of buttons, not via inline typing.
8. **No waveform / scrubber.** Playback is just a Play/Pause button. No timeline, no scrub, no segment regen.
9. **No history actions beyond "reuse".** No play, copy, delete; tapping plays the underlying file only because `loadHistory` calls `audioPlayer.load`.
10. **Settings is a `.sheet`, not a `Settings` scene.** Means ⌘, doesn't work and there is no native preferences chrome.
11. **Custom Voices is a `.sheet`.** Should be a destination in the sidebar.
12. **Generation is unbounded.** No max‑tokens guard, no character cap, no warning when the text is very long.
13. **No command palette / keyboard shortcuts.** Nothing for ⌘K, ⌘G (generate), ⌘L (focus prompt), space (play/pause), etc.
14. **Minor:** `default.profraw` is sitting at the repo root (build artefact, should be `.gitignore`d).
15. **Minor:** `referenceText` field uses `lineLimit(2, reservesSpace: true)` so long transcripts truncate visually.

## How the "Electron-style bar" is actually behaving

Concretely: when you launch the app you see, from top to bottom,

1. A grey ~28‑pt macOS titlebar with traffic lights on the left and the string "Generation + History" centred — this is just `NSWindow` doing its default thing because the window does not set `titlebarAppearsTransparent`, `.windowStyle(.hiddenTitleBar)`, or `.toolbar`.
2. Immediately below, the dark blue/black `VoiceForgeTheme.sidebar` panel which contains its own "VoiceForge — Instant text to speech" wordmark.

The visual duplication (two stacked title bars with two different fonts and two different background colours) is the entire "Electron" feeling. Fix is exactly what the redesign plan calls for: hide the default titlebar, attach a `.toolbar` that contains the wordmark + state pill + Generate button, and let the `NavigationSplitView` sidebar be the only sidebar.

## Conclusion

VoiceForge today is a functional but conceptually thin local TTS app. The "does it work" answer is **yes**: if `mlx-speech` is installed (it is on this machine), pressing Generate produces a real WAV and plays it. The "is it native" answer is **yes**: pure SwiftUI + AppKit interop, no Electron in sight. The "does it feel native" answer is **no**, primarily because of the default-titlebar issue and the lack of `NavigationSplitView`/`Inspector` semantics. The redesign in `2026-05-10-redesign-plan.md` addresses all of that.
